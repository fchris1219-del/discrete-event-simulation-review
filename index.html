1.1

系统、模型与仿真 简答必考

三个核心概念（张口能答）

必考系统：由相互关联的实体组成、能完成某种功能的整体。研究三要素 = 实体、属性、活动。

必考模型：对系统特征和规律的准确描述、表现或抽象。三性质 = 相似性、简化性、多样性。

必考仿真：利用模型模仿实际系统运行过程（"用模型做实验"）。现代指计算机仿真。

三者关系（高频简答）

三者之间存在三个活动，构成三角关系：

活动含义别称
系统建模观测实际系统，建立数学逻辑模型（理论模型）一次建模
仿真建模将理论模型转为可在计算机运行的仿真程序二次建模
仿真实验运行仿真程序，分析结果认识系统—
核心关系句（背下来）

系统是研究的对象，模型是系统的抽象（是仿真的桥梁），而试验是仿真的手段。

模型的分类（名词解释）

分类类型说明
按构造方式实体模型（物理模型）根据相似性建立的实物模型，直观但成本高
数学模型用文字、数学、逻辑等抽象描述，灵活经济
按描述层次理论模型（一次建模）对系统的理论描述，如排队论模型
仿真模型（二次建模）能在计算机运行的模型，如GPSS程序
1.2

仿真分类、步骤与习题

仿真分类——四个维度（填空/选择高频）

从四个维度分类，每个维度都可能出现在填空或选择题中。

① 按模型的构造方式

物理仿真
  • 在实体模型（物理模型）上进行实验
  • 计算机问世前的主要形式，又称"模拟"
  • 优点直观形象，缺点成本高
数学仿真（计算机仿真）
  • 在数学模型上进行实验，通过计算机程序实现
  • 灵活、经济、可重复，今天说的仿真通常指此

还有半实物仿真：数学模型与物理模型结合，复杂部分用数学模型，关键部分用实物。

② 按系统模型特性

类型特征描述工具仿真目标
连续系统仿真状态变量连续变化微分方程、差分方程获得状态变量的动态变化过程
离散事件系统仿真状态只在离散时刻跳跃变化，具有随机性概率分布、排队论、ACD获得系统行为的统计性能
离散事件系统仿真目标（重要）

目标是获得系统行为的统计性能，而不是状态变量的动态变化过程。因为含随机因素，一次仿真只是一次采样，只有统计意义才有参考价值。

③ 按仿真计算机类型

类型特征现状
模拟计算机仿真使用模拟计算机，本质上是并行仿真已逐步被淘汰
数字计算机仿真将数学模型用程序实现当今主流
数字模拟混合仿真结合两者优点已被全数字仿真取代

④ 按仿真时钟与实际时钟的比例关系 选择题

类型关系特征应用场景
实时仿真仿真时钟 = 实际时钟仿真速度与实际系统相同飞行训练模拟器；在线仿真
亚实时仿真仿真时钟 < 实际时钟（慢）仿真速度慢于实际系统大多数系统的离线研究与分析；又称离线仿真
超实时仿真仿真时钟 > 实际时钟（快）仿真速度快于实际系统大气环流、交通系统等需压缩时间的仿真

仿真的十个基本步骤（简答题）

完成计算机仿真需要经过3个大活动（系统建模、仿真建模、仿真实验），细化为10个步骤：

  1. 1
    问题描述与系统定义
    明确仿真目的和任务，正确定义系统边界、组成和环境，确定目标函数。这一步最关键，直接影响仿真质量。
  2. 2
    建立系统模型
    分析系统各组成部分的状态变化和参数关系，建立系统的数学逻辑模型（理论模型，即一次建模）。
  3. 3
    收集和整理数据资料
    收集随机变量的分布函数及参数，以及各组成部分相互关系的定性资料。数据正确性直接影响仿真输出。
  4. 4
    建立仿真模型，设计程序
    将理论模型转变为仿真程序（二次建模）。同时进行模型验证（Verification）：考察程序是否正确反映了数学逻辑模型。
  5. 5
    调试程序，确认模型
    运行调试性仿真，进行模型确认（Validation）：检验数学逻辑模型是否正确反映了现实系统的本质。
  6. 6
    实验设计
    设定不同可控变量与参数组合、系统初始条件、仿真运行长度、随机样本大小和独立仿真运行次数等。
  7. 7
    计算机仿真运行
    根据实验设计运行仿真，获取仿真输出数据，详细记录每次仿真的输入参数和输出结果。
  8. 8
    仿真结果分析
    计算样本均值、均方差、置信区间等统计指标；进行灵敏度分析；依据目标函数选择较优方案。
  9. 9
    建立文档
    将经过验证确认的系统模型、仿真程序以及输入输出资料和分析结论建立文档，供后续参考和改进。
  10. 10
    实施仿真决策
    将仿真辅助作出的管理决策付诸实施。

易混淆：模型验证 vs 模型确认

这两个概念要分清——出现在步骤4和步骤5

模型验证（Verification）：验证仿真程序是否正确实现了数学逻辑模型。"程序层面"——程序有没有Bug？（步骤4完成）

模型确认（Validation）：确认数学逻辑模型是否正确反映了现实系统本质。"模型层面"——模型建得对不对？（步骤5完成）

Validation是比Verification更高层次的确认，两者在仿真步骤中发生在不同阶段。

仿真软件的三类分类（1.13考点）

类别代表软件特点灵活性建模效率
第一类 通用编程语言C、C++、Java对开发者要求高，仿真机制需自行实现最高最低
第二类 仿真编程语言GPSS/H、SIMAN V、SLAM II、GPSSWorld封装了仿真基本机制（仿真钟推进、算法实现），保持灵活性和通用性较高中等
第三类 仿真环境Arena、Witness、Flexsim、Anylogic图形化用户界面，图形化建模较低最高
GPSSWorld的定位

GPSSWorld同时具备第二类和第三类的特点：保留GPSS语言的通用性和灵活性（第二类），同时适应图形化、集成化趋势（第三类）。从第一类到第三类：灵活性依次降低，建模效率依次提高。

课后习题（推荐做：1.1-1.6, 1.13）

做这几题基本覆盖全章内容。题目原文 + 解答要点如下：

1.1简述什么是系统和系统的分类。
答系统：由若干相互关联、相互作用的实体组成、能完成某种功能的有机整体。研究系统关注实体、属性、活动三方面。分类：①按状态变化——连续系统 / 离散事件系统；②按随机性——确定性系统 / 随机性系统；③按时间特性——静态系统 / 动态系统。
1.2简述什么是模型和模型的分类。
答模型：根据研究目的，对所研究系统的特征和规律的准确描述、表现或抽象，用于提供关于系统的有用信息。模型有相似性、简化性、多样性三个性质。分类：①按构造方式——实体模型（物理模型）/ 数学模型；②按描述层次——理论模型（一次建模）/ 仿真模型（二次建模）。
1.3简述什么是仿真和仿真的分类。
答仿真：利用模型来模仿实际系统的运行过程，以达到研究实际系统目的的活动（"用模型做实验"）。分类：①按模型构造方式——物理仿真 / 数学仿真（计算机仿真）/ 半实物仿真；②按系统模型特性——连续系统仿真 / 离散事件系统仿真；③按计算机类型——模拟 / 数字 / 混合仿真；④按仿真时钟与实际时钟比例——实时 / 亚实时 / 超实时仿真。
1.4人们在研究较为复杂的系统时，通常用哪两种研究方法？仿真属于哪种？
答通常用两种研究方法：解析法（数学分析法）和仿真法（实验法）。解析法通过建立数学方程直接求解；仿真法通过建立模型做实验来获得系统行为。仿真属于实验法（仿真法）——它不直接对系统操作，而是对系统的模型进行实验。
1.5简述什么是计算机仿真。
答计算机仿真是以控制理论、相似原理、系统技术、信息技术、计算机技术及应用领域专业技术为基础，以计算机和各种专用物理效应设备为工具，通过建立模型对真实和设计的系统，按一定实验方案，通过数值计算方法展开系统模型进行试验来获得系统动态行为，并对结果进行分析研究、进而做出决策的一门综合性的试验性技术。简单说：用计算机和模型对系统进行实验研究。
1.6简述计算机仿真的三要素及联系三要素的三活动。
答三要素：系统、模型、计算机。三活动：①系统建模（联系系统和模型）——观测实际系统建立数学逻辑模型；②仿真建模（联系模型和计算机）——将理论模型转为可在计算机运行的仿真程序；③仿真实验（联系系统和计算机）——运行仿真程序分析结果认识系统。一句话：系统是研究对象，模型是仿真的桥梁，试验是仿真的手段。
1.13仿真软件可以分成哪三类？对每一类至少举出一例。
答仿真软件分三类：
① 通用编程语言：如 C、C++、Java。灵活性最高但建模效率最低。
② 仿真编程语言：如 GPSS/H、SIMAN V、SLAM II、GPSSWorld。封装了仿真基本机制（仿真钟推进、算法实现），保持灵活性同时提高效率。
③ 仿真环境：如 Arena、Witness、Flexsim、Anylogic。图形化界面建模，效率最高但灵活性最低。
从第一类到第三类：灵活性/通用性依次降低，建模效率依次提高。GPSSWorld兼具第二、三类特点。

离散事件系统建模仿真基本原理

2.1

基本术语 名词解释

以单人理发店系统（例2.1）为统一背景理解所有术语。这是整本书最基础的例子，考试也经常用它出题。

背景系统说明

单人理发店系统：只有一位理发师，顾客以一定速率到达。若理发师有空则立刻理发，否则排队等待。理发完成后离开。性能指标：理发师利用率、顾客平均等待时间、最大排队长度等。

实体 Entity
与研究目的有关的构成系统的各种成分，是系统边界内的对象。实体可以是物理的也可以是逻辑的。系统内包含哪些实体（系统的边界）通常与研究目的密切相关。
理发店中：理发师、顾客、顾客队列都是实体
临时实体（主动实体）永久实体（被动实体）
定义在系统中只存在一段时间的实体。从系统外部到达，通过系统，最后离开或被消耗永久驻留在系统中的实体，只要系统处于活动状态就存在
主动性具有主动性——其行为能引起系统中其他实体的行为/属性/状态的变化具有被动性——只有在主动实体的作用下才能改变
理发店例子顾客（到达→排队→被服务→离开）理发师、顾客队列
GPSSWorld对应活动实体（Transaction）设施（Facility）、存储器（Storage）、队列（Queue）等
属性 Attribute
实体由它的属性来描述。属性用来反映实体的某些性质，可以用参数或状态变量加以描述。
顾客的属性：到达时间、性别；理发师的属性：忙闲状态；队列的属性：队列长度
静态属性

值一旦确定后不再随时间变化。例：顾客的到达时间、性别（进入系统后固定）

动态属性

随时间不断变化。例：理发师的忙闲状态、队列的长度

属性选取三原则：①便于排队规则的确定（如到达时间→FIFO）；②便于实体的分类和行为描述（如性别→不同服务时间）；③便于信息的统计分析（如队长→平均等待队长统计）
状态 State
系统状态：在某一确定时间，系统中所有实体的状态（动态属性）的集合。实体状态：对实体活动特征状况或性态的划分，表征量为状态变量。
理发店某时刻状态：StQ(t)=2, StS(t)=1，意味着此时队列中有2人等待，理发师正在服务
事件 Event
引起系统状态发生变化的瞬间操作或行为。注意：事件是瞬间发生的，不占时间，这与"活动"不同。系统的运行可以看作是由事件驱动的。
理发店中的三类事件：①"顾客到达"②"开始服务"（条件事件）③"顾客离开/服务完成"
确定事件（Bound Event）条件事件（Conditional Event）
定义发生时间可以事先确定的事件发生时间依赖于系统状态而不能事先确定的事件
理发店例子"顾客到达"——可提前计算下一到达时间；"顾客离开"——开始服务后可确定完成时间"开始服务"——只有顾客在队首且理发师空闲时才发生，时间不确定
ES中处理直接建立事件例程隐含在确定事件例程中，不单独建立例程
活动 Activity
实体在两个事件之间保持某一状态的持续过程（占一段时间）。活动的开始和结束都由事件引起。
理发店中：顾客"排队等待"是活动（条件活动，时长不确定）；"理发"是活动（确定活动，时长由采样确定）
事件 vs 活动 的本质区别

事件是瞬间的（不占时间），活动是持续的（占一段时间）。活动的开始事件发生，活动开始；活动的结束事件发生，活动结束。

进程 Process
由与某类实体相关的若干事件及活动组成，描述该类实体完整生命周期（从产生到消亡）的有序集合。进程 = 若干活动 + 若干事件的时序组合。
顾客的进程：到达事件→排队活动→开始服务事件→理发活动→离开事件
粒度由小到大：事件 < 活动 < 进程。活动由两个事件界定，进程由若干事件和活动按时序和逻辑关系组成。
规则 Rule
描述实体之间逻辑关系和运行策略的约定。规则决定了系统的行为方式。
理发店规则：FIFO先来先服务；优先服务等待时间最长的顾客；多理发师时顾客喜欢找1号师
术语一句话定义是否占时间理发店例子
实体Entity组成系统的物理/逻辑单元—顾客/理发师/队列
属性Attribute实体特征的描述参数—理发师忙闲、队长
状态State某时刻所有实体动态属性的集合—(StS=1, StQ=2)
事件Event引起状态变化的瞬间操作❌ 不占到达/开始服务/离开
活动Activity两事件间保持某状态的持续过程✅ 占一段排队/理发
进程Process某类实体的完整生命周期✅ 含若干活动到达→排队→服务→离开
规则Rule描述实体逻辑关系和运行策略—FIFO先来先服务

四种仿真策略 PI必考

最重要的考点

GPSSWorld的仿真策略是进程交互法（PI）——考到概率极大，必须记牢，还要能说出PI特点与其他三种策略的区别。

事件调度法（Event Scheduling，ES）

基本模型单元：事件例程（每类确定事件对应一个处理例程）

时钟推进：推进到事件表中下一最早确定事件发生时刻

条件事件处理：不单独建立例程，隐含在相关确定事件例程中

特点：效率高、时钟精确，但每个事件例程建模复杂（需嵌入条件判断逻辑），工作量大，建模不直观

代表语言：GASP、SIMSCRIPT

活动扫描法（Activity Scanning，AS）

基本模型单元：活动例程（确定活动和条件活动各建一个例程）

时钟推进：各主动实体时间元 T(i)（实体仿真钟）中的最小值

条件事件处理：建立独立的条件活动例程，通过反复扫描执行（扫描到测试条件为True时执行）

特点：各活动例程独立、建模简单，对应ACD；但反复扫描效率低，做大量无用功

代表语言：CSL（1962年 Buxton & Laski 提出）

三段扫描法（Three-Phase Scanning，3PS）

基本模型单元：活动例程，分B类（确定/Bound）和C类（条件/Conditional）两类

时钟推进：推进到下一最早B类例程调用时刻（A段）

三段执行：A段时间推进→B段执行到时B类例程→C段扫描条件C类例程

特点：3PS是AS的改进，兼有ES的高效时钟推进和AS的简单建模。B类不需扫描，只有C类扫描。

改进来源：Tocher（1963年）

进程交互法（Process Interaction，PI）★GPSSWorld★

基本模型单元：实体进程例程（描述实体完整生命周期）

时钟推进：推进到FEL中最早的无条件延迟复活点时刻

两种延迟：无条件延迟（可预知，放FEL）/ 条件延迟（取决状态，放CEL）

两张事件表：当前事件表（CEL：复活点≤当前时钟）/ 未来事件表（FEL：复活点>当前时钟）

特点：建模最直观（进程对应实体真实生命周期），但实现最复杂，通常需要仿真语言支持

代表语言：GPSS、SIMULA、GPSSWorld

PI的CEL/FEL机制详解

当前事件表（CEL）
  • 复活点时间 ≤ 当前仿真时钟的实体
  • 即"现在有资格执行"的实体
  • 包含正在处理但条件尚未满足的实体（条件延迟）
  • 扫描CEL，推进可推进的进程
未来事件表（FEL）
  • 复活点时间 > 当前仿真时钟的实体
  • 即"将来某确定时刻才能继续"的实体（无条件延迟）
  • 每次从FEL取最早复活时间，推进仿真钟
PI的两种延迟（简答可能考）

无条件延迟：延迟期可事先确定（如理发时间），实体放入未来事件表FEL等待。例：顾客在"理发"状态，停留直到服务完成。

条件延迟：延迟期取决于系统状态，不能事先确定，实体放入当前事件表CEL等待。例：顾客在"排队"状态，等待直到处于队首且理发师空闲。

★手工仿真（例2.6）必考大题

手工仿真的执行步骤（事件调度法）

手工仿真表的每一步都在模拟事件调度法的执行过程。掌握这4步，就能独立填写任何手工仿真表。

  1. 1
    从事件表中找最早事件
    将事件表中发生时间最小的事件取出，将仿真时钟推进到该时刻。若有多个事件同时发生（同一时刻），按解结规则处理。
  2. 2
    判断事件类型，执行对应逻辑
    若是到达事件 A(i,t)：①产生下一顾客到达事件（t+到达间隔，插入事件表）；②判断理发师状态——空闲则开始服务（产生离开事件，StS=1），忙则排队（StQ+1）。
    若是离开事件 D(i,t)：①C+1，B加上本次服务时长；②判断队列——非空则继续服务下一人（StQ-1，产生新离开事件，W+=等待时长），队列空则理发师置闲（StS=0）。
  3. 3
    更新系统状态和统计计数器
    更新 StQ(t) 和 StS(t)，更新 C、B、W。注意 W 只在顾客开始接受服务时更新（W += 开始服务时刻 − 到达时刻）。
  4. 4
    维护事件表，进入下一步
    删除已处理的事件，把新产生的事件按时间先后插入事件表，准备下一轮循环。
解结规则（同时事件的处理顺序）——必须记住

当同一时刻有多个事件同时发生时，需要规定处理顺序，这称为解结规则。书中（例2.6）的解结规则：当顾客到达事件和顾客离开事件同时发生时，先处理"离开"事件，再处理"到达"事件。

原因：先处理离开可以让理发师先空出来，刚到达的顾客可能直接开始服务，更符合实际。不同题目的解结规则可能不同，注意看题目说明。

顾客到达事件例程
  • 产生下一个顾客到达事件（插入事件表）
  • IF 理发师空闲：置理发师"忙"（StS=1）；产生服务时间；安排服务结束事件
  • ELSE（理发师忙）：排队（StQ+1）
服务完毕/顾客离开事件例程
  • 顾客完成数 C+1
  • IF 队列非空（StQ > 0）：StQ-1；产生服务时间；安排下一顾客服务结束事件；W += 该顾客等待时长
  • ELSE（队列为空）：置理发师"闲"（StS=0）

课后习题（推荐做：2.1-2.6, 2.8, 2.9, 2.16）

题目原文 + 解答要点如下。2.16是手工仿真重点练习题，与例2.6同类型但是双理发师。

2.1什么是实体？实体分成哪两类？试举例说明。
答实体：与研究目的有关的构成系统的各种成分，是系统边界内的对象。分两类：
① 临时实体（主动实体）：在系统中只存在一段时间，从外部到达、通过系统、最后离开或被消耗。具有主动性。例：理发店的顾客。
② 永久实体（被动实体）：永久驻留在系统中，是系统活动的必要条件。具有被动性。例：理发店的理发师、队列。
2.2什么是实体的属性？进行仿真建模时选取属性应考虑的原则有哪些？
答属性：用来反映实体某些性质的描述，可用参数或状态变量表示（分静态属性和动态属性）。选取原则：
  • 便于排队规则的确定（如将到达时间作为属性，便于实现先来先服务）
  • 便于实体的分类和行为的描述（如将性别作为属性，区分不同理发时间）
  • 便于信息的统计分析（如将队长作为队列属性，便于统计平均队长）
2.3在离散事件系统中，什么是事件、活动和进程？它们之间存在着怎样的关系？
答事件：引起系统状态发生变化的瞬间操作（不占时间）。活动：实体在两个事件之间保持某一状态的持续过程（占一段时间）。进程：由和某类实体相关的若干事件及活动组成，描述其完整生命周期。关系：粒度由小到大为 事件 < 活动 < 进程。活动由两个事件界定（开始事件和结束事件），进程由若干事件和活动按时序和逻辑关系组成。
2.4仿真钟的推进方式有哪两种？分析比较它们的优缺点。
答两种推进方式：
① 事件单位推进法（变步长法）：从一个事件时刻直接推进到下一事件时刻，跳过无事件的时间段。优点：效率高、精确不漏事件；缺点：设计实现较复杂。离散事件系统首选此法（GPSSWorld采用）。
② 时间单位推进法（固定步长法）：选固定步长，每步检查是否有事件发生。优点：实现简单；缺点：可能误差（同步内多事件视为同时）、步长难定。
适用：事件单位推进适合离散事件系统；时间单位推进适合周期性强的模型。
2.5简述进程交互法中的条件延迟和无条件延迟，并各举一例说明。
答无条件延迟：实体停留在进程某点，直到预先确定的延迟期满为止，延迟时间可事先确定。放入未来事件表FEL。例：顾客在"理发"状态，停留直到服务完成（理发时间可事先采样确定）。
条件延迟：延迟期长短与系统状态有关、不能事先确定，实体停留直到条件满足才能继续。放入当前事件表CEL。例：顾客在"排队"状态，等待直到处于队首且理发师空闲。
2.6常用的仿真策略/处理方式有哪几种？试分析比较。
答四种策略：
① 事件调度法ES：基本单元是事件例程，时钟推进到下一最早确定事件，条件事件隐含在确定事件中。效率高但建模复杂。
② 活动扫描法AS：基本单元是活动例程，按时间元最小值推进，反复扫描活动条件。建模简单但效率低。
③ 三段扫描法3PS：AS的改进，活动分B类（确定）和C类（条件），兼顾ES高效和AS简单。
④ 进程交互法PI：基本单元是实体进程，用CEL/FEL两张表。最直观，GPSSWorld采用此法。
2.8离散事件系统仿真中，确定事件发生时间的方式有哪两种？
答两种方式：
① 直接方式：直接给定事件发生的时间点（确定事件的策划方式）。例：服务时间已知，直接计算出服务结束时间。
② 间接方式：给出事件发生的条件，事件在条件满足时发生（条件事件的策划方式）。例："服务开始"在队首有顾客且理发师空闲时发生。
2.9离散事件系统仿真中可以采用的仿真策略有哪些？试比较分析。
答同2.6，可采用事件调度法（ES）、活动扫描法（AS）、三段扫描法（3PS）、进程交互法（PI）四种。比较见下表关键点：ES以事件为单元效率高建模难；AS以活动为单元建模简单效率低；3PS是AS的改进兼顾两者优点；PI以进程为单元最直观、是GPSSWorld的策略。

GENERATE 五参数（必须背熟）

GENERATE A,B,C,D,E

A=时间间隔均值 / B=半区间(间隔在A±B均匀分布,若B是函数则A×B) / C=第一个实体产生时刻 / D=产生实体总数限制 / E=优先级(0~127)

省略只能省数值不能省逗号:GENERATE 7,,,,1=只指定优先级1

模块格式功能·进入模式
ADVANCEA,B延时A±B(服务过程)。无条件进入
TERMINATEA实体消失,终止计数器减A。配合START
SEIZEA占用设施A(只能1个实体)。有条件进入
RELEASEA释放设施A。无条件进入。必须与SEIZE成对
QUEUEA,B进入队列A,队长+B(默认1)。无条件进入
DEPARTA,B离开队列A,队长-B(默认1)。无条件进入
STORAGENAME STORAGE A定义存储器(说明部分),容量A
ENTERA,B进入存储器A占B个单位。有条件进入
LEAVEA,B离开存储器A释放B个单位。无条件进入
ASSIGNA,B,C给参数A赋值B(可+/-累加),C为函数号
PRIORITYA设置实体优先级为A
STARTA开始仿真,终止计数器初值A
RESET = 仿真预热(必须会写)

RESET清空统计数据但不清除活动实体。预热模式:

START 100 ; 预热运行100个
RESET ; 清空统计(实体不清)
START 1000 ; 正式仿真统计

区别:RESET不清实体,CLEAR清实体+时钟归零

3.2

TRANSFER三模式 考试就这三种

三种必考模式

① 无条件转向:TRANSFER ,B → 无条件去标号B

② 概率转向:TRANSFER A,B,C → 以A概率去C,1-A概率去B(B省略则去下一模块)

③ BOTH模式:TRANSFER BOTH,B,C → 先试B,B进不去再试C,都进不去则停留等待

补充:PICK模式

TRANSFER PICK,A,B → 在A到B范围内随机选一个模块。常与BOTH配合实现"随机选+若忙则换"。

TERMINATE 1
START 1000
两个关键点

① BOTH模式执行:先测ADD_A的SEIZE能否进入,被拒则测ADD_B,都被拒则停留在TRANSFER等待。

② ADD_A路径的TERMINATE不能缺省,否则经过理发师A的顾客还会继续进入理发师B的处理。

结果:进A的550个(利用率0.757),进B的451个(利用率0.626),优先A体现出来了。

这两个模块中,若第2个参数是函数SNA码,则两参数关系为A×B(不是A±B)。所以指数分布用 ADVANCE 10#FN$EXPON 或 ADVANCE FN$EXPON,10。

4.3

TEST / GATE / SELECT 执行规则要懂

TEST — 比较两个数值

TEST O A,B,C

O=运算符(E相等/NE不等/L小于/LE小于等于/G大于/GE大于等于);A,B=比较对象;C=不满足时去的地址。

执行规则:按O比较A和B,满足则通过进下一模块;不满足则去C;若C省略则实体停在上一模块等待,直到条件满足。

GATE — 测试固定实体状态

GATE O A,B

O=状态码(U占用/NU未占用/I空闲;SF满/SNF不满/SE空/SNE非空;LS开/LR关);A=实体名;B=不满足时去的地址(省略则等待)。

GATE比TEST效率高:只在状态变化时才测试。能用GATE就不用TEST。

SELECT — 从多个实体选一个(六参数要懂)

SELECT O A,B,C,D,E,F

A=存放所选实体号的参数 / B=扫描最小编号 / C=扫描最大编号 / D=比较数值 / E=实体族名(S存储器/Q队列/F设施) / F=找不到时的去处

三种模式:

关系模式(O=E/NE/G/GE/L/LE):选第一个满足关系的

极值模式(O=MAX/MIN):选最大/最小,D和F省略

逻辑模式(O=FNV/FV/SE/SF/LS/LR等):选满足逻辑条件的,D和E省略

SELECT 示例
SELECT MIN 1,1,4,,Q ; 1~4号队列选最短的,号码存入参数1
SELECT E 2,1,3,0,F ; 1~3号设施找状态=0(闲)的,号存参数2,全忙则参数2置0
SELECT NU 1,2,5 ; 2~5号设施找空闲的,最小号存参数1

5.2

★LOOP循环 高频必会

LOOP A,B 执行规则

LOOP A,B → 参数A的值先减1,然后判断:若>0则跳到标号B;若≤0则继续向下执行。

A=控制循环次数的参数号(必须已存在且为正);B=循环体起始模块标号。

书中例子LOOP基础用法
累加5次
GENERATE 10
ASSIGN 1,5 ; 参数1=循环次数5
LP SAVEVALUE 1+,P1 ; 保存值1 += 参数1
LOOP 1,LP ; 参数1减1,>0回LP(注意A用"1"不是"P1")
TERMINATE 1
START 1
结果分析

SAVEVALUE执行5次:第1次P1=5加5,第2次P1=4加4...因为LOOP每次让P1减1。最终保存值=5+4+3+2+1=15。

易错:LOOP的A参数写"1"(参数号)不是"P1"(参数值)。

5.3

SPLIT / ASSEMBLE / GATHER / MATCH

模块格式功能
SPLITA,B,C复制A个子体,转去标号B;母体继续。母子体共享装配编号A1
ASSEMBLEA等A个相同装配号实体到齐,合并为1个(消耗其余A-1个)
GATHERA等A个实体到齐,全部放行(都不消耗,不要求装配号相同)
MATCHLABEL两进程同步点,配对实体互等
★ASSEMBLE vs GATHER(必考区分点)

ASSEMBLE A:A个相同装配编号实体到齐,合并为1个继续,其余被消除。(消耗实体)

GATHER A:A个实体到齐,全部继续,都不消除,不要求装配编号相同。(纯同步,不消耗)

SPLIT+ASSEMBLE典型场景

顾客到达后同时进行多个并行服务(如洗头+修指甲),全部完成后再付款。SPLIT复制子体走不同服务路径,ASSEMBLE等所有子体完成后合并。

01 GPSS World 核心概念

GPSS（General Purpose Simulation System）是专门用于离散事件系统仿真的语言。GPSS World 是它在 Windows 平台上的可视化集成环境。

核心思想：把现实系统抽象成活动实体（Transaction，事务）在固定实体（设施、存储器、队列等）之间流动的过程。程序就是描述这个流动轨迹的模块序列。

两种模型表示：框图式模型（画流程图，不能直接执行）和程序式模型（写代码，可以运行）。一般先画框图再写程序。

考试重点：理解"活动实体在模块之间流动"这个核心机制。所有的 block 都是在描述活动实体会经历什么。
02 实体分类

活动实体（Transaction）

系统中可以移动的人、设备、信息等。是驱动 GPSS World 程序运行的原动力，程序的灵魂。每个活动实体有以下属性：

属性说明
优先级竞争资源时的优先权，0~127，越大越优先，默认0
标记时间实体产生的绝对时钟值
装配号每个实体自带的正整数编号，用于 SPLIT/ASSEMBLE/MATCH
参数实体可携带的属性值，用 ASSIGN 赋值，用 Pj 读取

固定实体

位置固定的资源和统计工具：

资源实体

类型说明相关模块
设施 FACILITY一次只能被一个实体占用的服务资源（理发师、跑道、收银台）SEIZE / RELEASE
队列 QUEUE等候区，用于统计排队信息QUEUE / DEPART
存储器 STORAGE可同时容纳多个实体的资源（停车场、仓库），需先用 STORAGE 定义容量ENTER / LEAVE
逻辑开关 LOGIC两种状态（开/关）的开关设备LOGIC S/R/I

统计实体

表格（TABLE）和保存值（SAVEVALUE）用于收集和存储统计数据。

设施 vs 存储器：设施只能被1个实体占用（单服务台）；存储器可以同时被多个实体占用（多服务台用多个设施，或用一个存储器容量=服务台数）。4个加油枪 = 4个设施 或 1个容量为4的存储器。
03 程序结构与语句格式

程序三部分

一个 GPSS World 程序包含 3 部分：

部分内容是否必须
说明部分定义语句：EQU、STORAGE、FUNCTION、VARIABLE、TABLE、INITIAL 等可选
模块部分模块语句序列，描述活动实体的行为轨迹必须
控制部分命令语句：START、RESET、CLEAR 等可选（但一般要有 START）

语句格式

每条语句占一行，最多250个字符，由5个数据域组成，空格分隔：

行号(可选) 语句标签(可选) 操作码(必须) 操作数(可选) ;注释(可选)
GENERATE 16,9 ;顾客每隔16±9分钟到来 QUEUE LINE ;进入队列LINE JOE SEIZE BARBER ;占用理发师BARBER DEPART LINE ;离开队列 ADVANCE 15,7 ;理发15±7分钟 RELEASE BARBER ;释放理发师 TERMINATE 1 ;离开系统 START 20 ;仿真20个顾客
注释：整行注释用 ; 或 * 开头；行内注释在数据域后面加 ;。
标签规则：不能用 SNA 码或系统关键字做标签。
04 初级模块语法（第3章）

与活动实体有关的模块

GENERATE — 产生活动实体
所有活动实体的入口。没有 GENERATE 就没有实体进入系统。
GENERATE A, B, C, D, E
A — 到达间隔均值
实体产生的时间间隔均值，默认0。可以是数值、名称、表达式、SNA码，但不能是实体参数。
B — 到达间隔半区间（或函数修正）
默认0。若A=16, B=9，则间隔在7~25之间均匀分布。若B是函数，则实际间隔=A×FN$函数名。
C — 首次到达时刻
第一个实体的产生时间，默认从仿真零时刻开始经过间隔A后产生。
D — 产生总数限制
默认不限。
E — 优先级
0~127，默认0，越大越优先。
GENERATE 16,9 ;均匀分布 U(7,25) GENERATE 10,FN$EXP ;指数分布，均值10 GENERATE ,,,1 ;只产生1个实体（计时器） GENERATE 100,,,1 ;100时刻产生1个实体
进入模式：不需要活动实体触发（这是活动实体的源头）
ADVANCE — 延时
让活动实体在仿真中停留一段时间（接受服务、等待等）。
ADVANCE A, B
A — 延迟均值（必须）
必须是正数。
B — 延迟半区间
默认0。与 GENERATE 的 B 操作数用法相同。
ADVANCE 15,7 ;延时 U(8,22) ADVANCE 20 ;固定延时20 ADVANCE 101.6,50.3 ;延时 U(51.3, 151.9)
进入模式：无条件进入
ASSIGN — 给活动实体参数赋值
设置或修改活动实体携带的参数。参数随实体存在而存在，随实体消亡（TERMINATE）而消失。
ASSIGN A, B, C
A — 参数编号或名称
可附加 + 或 - 表示在原值基础上增减。
B — 赋值/增减的值
必须是名称、数值、字符串、表达式、SNA码。
C — 函数编号（可选）
用于函数修正。
ASSIGN 1,2 ;参数1 = 2 ASSIGN 1+,3 ;参数1 = 参数1 + 3 ASSIGN 1-,3 ;参数1 = 参数1 - 3 ASSIGN B_1,5 ;名为B_1的参数 = 5
进入模式：无条件进入
TRANSFER — 转向
让活动实体跳转到指定模块，类似高级语言的 goto。共有9种跳转模式。
TRANSFER A, B, C, D

1. 无条件转向（A省略）

TRANSFER ,ADD ;无条件跳转到标签ADD

2. 概率转向（A是小数）

TRANSFER 0.75,ADDB,ADDC ;75%去ADDC，25%去ADDB TRANSFER .75,,ADDC ;75%去ADDC，25%去下一模块

规则：以概率A转向C，以概率(1-A)转向B（B省略则去下一模块）。若目标模块拒绝进入则等待。

3. BOTH模式

TRANSFER BOTH,ADDB,ADDC ;先试B，不行试C，都不行等待

注意：B域地址的模块一定是有条件进入模块（如 SEIZE）才有意义。

4. ALL模式

TRANSFER ALL,ADDB,ADDC,3 ;从ADDB到ADDC每隔3个模块尝试进入

D默认1。从B开始按步长D逐个尝试到C，都拒绝则等待下次重试。C必须在B后面且C-B能被D整除。

5. PICK模式

TRANSFER PICK,ADDB,ADDC ;随机选择ADDB或ADDC进入

从B到C之间随机选一个模块进入，进不去则等待。与BOTH的区别：BOTH优先B，PICK随机。

6. P参数模式

TRANSFER P,1,2 ;去参数1的值+2所指的模块

取实体参数Placemarker的值加上C，作为目标地址。

7. SBR子程序模式

TRANSFER SBR,New_Place,Placemarker

无条件转向B，同时将当前位置存入参数Placemarker（用于返回）。

8. FN函数模式

TRANSFER FN,FN_NAME ;按函数值决定去向

9. SIM同时模式

TRANSFER SIM,Nodelay_Place,Delay_Place

检查延迟标志：被设置(set)则去Delay_Place并复位；被复位(reset)则去Nodelay_Place。

进入模式：无条件进入
PRIORITY — 改变优先级
PRIORITY A, B
A — 新优先级
0~127之间的值。
B — 可选，BU
省略或缺省：放回CEC中同优先级实体前面；BU：放在同优先级实体之后。
进入模式：无条件进入
BUFFER — 重新调度
将活动实体放到CEC中同优先级实体的后面（让其他同优先级的先处理）。
BUFFER

没有参数。主要用于提高仿真运行效率。

进入模式：无条件进入
TERMINATE — 消除活动实体
活动实体的出口。GENERATE 是入口，TERMINATE 是出口，成对使用。
TERMINATE A
A — 从仿真终止计数器减去的数
默认0。与 START 配合控制仿真终止。
TERMINATE 1 ;减去1，配合 START 20 = 仿真20个实体后停止 TERMINATE ;减去0，实体消亡但不影响仿真终止计数器
关键：仿真终止计数器的初值由 START 的 A 操作数给定。每有实体经过 TERMINATE，计数器减去该 TERMINATE 的 A 值。减到 ≤ 0 时仿真停止。计数器的终值不一定等于仿真的实体数目（因为可能有多个 TERMINATE，且 A 值不一定是1）。
进入模式：无条件进入（终止模块，后面不能有模块）

与设施有关的模块

SEIZE — 占用设施
尝试占用一个设施。如果设施空闲则占用，否则在设施的延迟链中等候。
SEIZE A
A — 设施编号或名称（必须）
进入模式：有条件进入（设施空闲时才能进入）
注意：SEIZE 和 RELEASE 必须成对出现，设施名必须一致。占用后必须释放，否则其他实体永远无法使用。实体进入 SEIZE 后，也一定要经过 RELEASE，否则不能 TERMINATE。
RELEASE — 释放设施
RELEASE A
A — 设施编号或名称（必须）
必须与前面的 SEIZE 对应。
进入模式：无条件进入

与队列有关的模块

QUEUE — 进入队列排队
用于统计排队过程。活动实体进入队列时自动开始计时。
QUEUE A, B
A — 队列编号或名称（必须）
B — 队长增加量（默认1）
进入模式：无条件进入
DEPART — 离开队列
DEPART A, B
A — 队列编号或名称（必须）
B — 队长减少量（默认1）
B 不能大于当前队长，否则报错。
进入模式：无条件进入
QUEUE/DEPART 使用要点：一般放在 SEIZE 的前后。QUEUE 放在 SEIZE 前面（开始等待），DEPART 放在 SEIZE 后面（等到了就离队）。一个队列可以有多个出口（多个 DEPART）。

与存储器有关的模块

STORAGE — 定义存储器容量（定义语句）
NAME STORAGE A
NAME — 存储器名称（必须，合法名称，不能是数字）
A — 容量（必须，正整数）
BAR STORAGE 10 ;定义存储器BAR，容量10

放在程序的说明部分（GENERATE 之前）。

ENTER — 进入存储器
ENTER A, B
A — 存储器编号或名称（必须）
B — 占用的容量（默认1）
进入模式：有条件进入（剩余容量 ≥ B 时才能进入）
LEAVE — 离开存储器
LEAVE A, B
A — 存储器编号或名称（必须）
B — 释放的容量（默认1）
B 不能大于当前存储量。
进入模式：无条件进入
05 中级模块与定义语句（第4章）

定义语句

EQU — 符号定义
给常量或表达式取一个名字，提高可读性。放在程序说明部分。值在仿真开始时就确定，之后不变。
NAME EQU X
Q_1 EQU 1 ;Q_1 代表数字 1 CONT EQU 1+2 ;CONT 代表 3 ABC EQU RN1 ;ABC 代表 RN1 在仿真开始时的值（固定）
注意：EQU 的 X 不能包含活动实体相关的 SNA 码（如 P1），因为定义时还没有活动实体。
VARIABLE — 变量定义
定义一个可重复计算的表达式。每次引用时重新计算（与 EQU 不同）。
NAME VARIABLE X
V_1 VARIABLE 2*P1 ;实体参数1的2倍 V_2 VARIABLE P1<2 ;逻辑表达式 V_MEAN VARIABLE 10+RN1@11 ;10~20均匀分布的随机整数 V_EXP VARIABLE -10#LOG(RN1/1000) ;指数分布

使用时用 V$NAME 引用变量的值。

FUNCTION — 函数定义
根据采样数据定义离散或连续的函数关系。至少占2行：定义行 + 数据行。
NAME FUNCTION A, B X1,Y1/X2,Y2/X3,Y3/...
A — 自变量
可以是 SNA 码、表达式。最常用 RNj（随机数发生器）。
B — 函数形式 + 数据点数
C = 连续值型，D = 离散值型，L = 列表值型，E = 属性值型，M = 属性列表值型。常用 C 和 D。

离散值型函数（D）

FN_BAR FUNCTION RN1,D5 0.15,3/0.4,4/0.7,5/0.9,6/1,7

数据行用的是累计概率。RN1∈[0,0.15)→3，[0.15,0.4)→4，[0.4,0.7)→5，[0.7,0.9)→6，[0.9,1)→7。

连续值型函数（C）

FN_BAR FUNCTION RN1,C6 0,0/0.15,3/0.4,4/0.7,5/0.9,6/1,7

数据点之间用线性内插。注意与离散型的区别：连续型的 X 数据行起点通常从0开始。

使用时用 FN$NAME 引用函数值。

RNj 说明：作为函数自变量时返回 0~0.999999 的均匀小数；直接用在整数表达式中返回 0~999 的均匀整数。
RMULT — 设定随机数种子
RMULT ,,234,,456

修改指定编号的随机数发生器种子。用于多次运行获得不同结果的统计实验。配合 CLEAR 使用。

中级模块

LOGIC — 逻辑开关控制
LOGIC O A
O — 辅助码（必须）
S = SET（置为打开/1），R = RESET（置为关闭/0），I = INVERT（取反）。
A — 逻辑开关编号或名称
LOGIC S L_BAR ;打开名为L_BAR的逻辑开关 LOGIC R P1 ;关闭参数1所指的逻辑开关 LOGIC I 1 ;取反1号逻辑开关

相关 SNA：LS$j 返回逻辑开关状态（1=开，0=关）。

进入模式：无条件进入
SAVEVALUE — 保存值
全局变量，不随活动实体消亡而消失（与参数 P 不同）。
SAVEVALUE A, B
A — 保存值编号或名称
可附加 + 或 -。
B — 要存放/增减的值
SAVEVALUE 1,2 ;保存值1 = 2 SAVEVALUE 1+,P2 ;保存值1 += 实体参数2的值 SAVEVALUE P1,5 ;参数1所指的保存值 = 5 SAVEVALUE 1-,X2 ;保存值1 -= 保存值2

相关 SNA：X$j 或 Xj 读取保存值。初值为0（或用 INITIAL 初始化）。遇到 CLEAR 恢复为0，遇到 RESET 保持不变。

进入模式：无条件进入
INITIAL — 初始化
初始化逻辑开关或保存值。放在说明部分。
INITIAL A, B
INITIAL LS1 ;1号逻辑开关初始为1（打开） INITIAL LS$L_BAR ;名为L_BAR的逻辑开关初始为1 INITIAL X1,5 ;1号保存值初始为5 INITIAL X$X_BAR,10 ;名为X_BAR的保存值初始为10

同一条 INITIAL 只能初始化一个实体。

TEST — 比较测试
比较两个数据的大小，根据结果控制活动实体走向。
TEST O A, B, C
O — 比较类型（必须）
E=等于, NE=不等, L=小于, LE=小于等于, G=大于, GE=大于等于。
A, B — 比较对象
C — 比较为假时跳转的地址（可选）
省略 C：条件满足才通过，否则等待（效率低）；有 C：条件满足则通过，否则跳转到 C。
TEST E Q2,3,ADD_BAR ;若队列2长度=3，通过；否则去ADD_BAR TEST GE X1,P1 ;若保存值1≥参数1，通过；否则等待
进入模式：有条件进入
GATE — 状态测试
测试设施、存储器、逻辑开关等实体的当前状态。效率比 TEST 高。
GATE O A, B
O — 状态代码（必须）
A — 实体编号或名称
B — 状态不匹配时跳转的地址（可选）
实体类型代码含义
设施U / NU在使用 / 未使用
设施I / NI被中断 / 未被中断
设施FV / FNV可用 / 不可用

进入模式：有条件进入
SELECT — 选择实体
从一组实体中按条件选择一个，将编号存入活动实体参数。

B — 扫描范围的最小编号
C — 扫描范围的最大编号
D — 比较值

居留时间与过境时间

M1 = 活动实体在系统中的居留时间（当前时钟 - 标记时间）。MP$j = 当前时钟 - 参数j的值（两点间经过的时间）。

表格实体

TABLE — 定义表格
NAME TABLE A, B, C, D
A — 要统计的数据项（SNA 码）
B — 第一区段上界
C — 中间区段宽度
D — 区段总数
T_STAY TABLE M1,5,5,20 ;统计居留时间M1，第一段≤5，每段宽5，共20段
TABULATE — 表格统计
TABULATE A, B
A — 表格名称或编号（必须）
B — 权重（默认1）
进入模式：无条件进入
QTABLE — 队列表格（定义语句）
专门统计队列等待时间的特殊表格，不需要 TABULATE 模块配合。
NAME QTABLE A, B, C, D

QTABLE 自动在 QUEUE/DEPART 时记录数据，比 TABLE+TABULATE 更简便。

循环与复制

LOOP — 循环
LOOP A, B
A — 循环计数参数（编号或名称，值必须已存在且为正数）
B — 循环体起始地址

执行规则：进入 LOOP 时，参数 A 减1。若减后 > 0，跳转到 B；若 ≤ 0，继续到下一模块。

GENERATE 10 ASSIGN 1,5 ;参数1=5（循环5次） LP SAVEVALUE 1+,P1 ;累加 LOOP 1,LP ;参数1减1，>0则回LP TERMINATE 1 START 1

注意：LOOP 的 A 操作数用的是参数编号"1"，不是"P1"。

进入模式：无条件进入
SPLIT — 复制活动实体
SPLIT A, B, C
A — 复制的子体数量
B — 子体去往的模块地址（省略则与母体走同一条路）
C — 用于区分母体和子体的参数编号（可选）
母体和子体通过参数C的不同值来区分。母体的C参数不变，第一个子体 = 母体C值+1，依次递增。

母体和子体具有相同的装配编号（A1），这是 ASSEMBLE/GATHER/MATCH 识别它们的依据。XN1（唯一编号）不同。

进入模式：无条件进入
ASSEMBLE — 装配
将同一装配集（A1相同）的多个实体合并为一个。
ASSEMBLE A
A — 需要聚集的实体数量

保留第一个到达的实体，其余消除。数量达到 A 后合并的实体继续前进。进入200个但只出来100个（如果 SPLIT 1 + ASSEMBLE 2）。

进入模式：无条件进入
GATHER — 聚集
与 ASSEMBLE 类似，但保留所有实体（不消除）。
GATHER A

等到同一装配集的 A 个实体都到达后，所有实体一起继续前进（数量不减少）。

进入模式：无条件进入
MATCH — 匹配
MATCH A
A — 配对 MATCH 模块的地址

两个 MATCH 成对使用。同一装配集的两个实体分别到达两个 MATCH 后，才同时放行。

进入模式：无条件进入

LINK A, B, C

C — 不进链时的跳转地址（可选）

C — 取出数量（ALL 表示全部取出）
D, E — 条件比较的参数

08 控制语句
START — 启动仿真
START A, B, C, D
A — 仿真终止计数器初值（必须，正整数）
B — NP 表示不打印标准报告；省略则打印
C — 不使用
D — 省略或0则打印CEC和FEC；非0不打印
START 100 ;仿真直到100个实体经过 TERMINATE（A=1的那些） START 1,NP ;仿真1个实体，不打印报告
RESET — 统计复位
清除统计数据和相对时钟，但不改变系统当前状态。用于预热系统。
RESET

无参数。保存值、逻辑开关、随机数种子、实体状态都不变。典型用法：先 START 预热，再 RESET，再 START 正式统计。

CLEAR — 完全清除
CLEAR A
A — ON（默认）全部恢复初始状态；OFF 保留保存值、逻辑开关、数组及随机数

CLEAR ON 比 RESET 更彻底——清除所有实体、统计、时钟，恢复到仿真开始前。配合 RMULT 用于多次独立运行。

RESET vs CLEAR：RESET 不改变系统状态（设施是否被占、实体在哪），只清统计数据，适合预热。CLEAR 彻底重置一切（或保留部分），适合多次独立实验。

01单理发师
学会最基本的7个block：GENERATE → QUEUE → SEIZE → DEPART → ADVANCE → RELEASE → TERMINATE + START

场景

一家理发店只有1个理发师Joe。顾客每隔16±9分钟到来，理发需要15±7分钟。仿真20个顾客。

新block速查

Block作用语法
GENERATE产生活动实体（顾客入口）GENERATE A,B — A是间隔均值，B是半区间
QUEUE进入队列（开始计时统计）QUEUE A — A是队列名称
SEIZE占用设施（有条件进入！空闲才能进）SEIZE A — A是设施名称
DEPART离开队列（停止计时统计）DEPART A — A是队列名称
ADVANCE延时（服务时间）ADVANCE A,B — A是均值，B是半区间
RELEASE释放设施RELEASE A — A是设施名称
TERMINATE实体离开系统TERMINATE A — A是终止计数器减去的数
核心逻辑：QUEUE在SEIZE前，DEPART在SEIZE后。SEIZE和RELEASE成对出现。TERMINATE的A配合START控制仿真何时停止。

例题程序

GENERATE 16,9 ;顾客每隔16±9分钟到来 QUEUE LINE ;进入名为LINE的队列 SEIZE JOE ;占用理发师JOE DEPART LINE ;离开队列（不再算等待时间） ADVANCE 15,7 ;理发15±7分钟 RELEASE JOE ;释放理发师 TERMINATE 1 ;离开系统，终止计数器减1 START 20 ;仿真直到20个实体经过TERMINATE

逐行解析

GENERATE 16,9：每隔16±9=7~25分钟产生一个顾客，均匀分布。

QUEUE/DEPART：纯统计用途，不影响实体流动。夹住SEIZE来统计等待时间。

SEIZE JOE：如果JOE空闲，占用它继续往下走；如果JOE忙，实体停在这里等（进入设施的延迟链）。这就是条件延迟。

ADVANCE 15,7：理发过程，时间确定，放入FEL。这就是无条件延迟。

TERMINATE 1 + START 20：每过一个顾客终止计数器减1，初值20，减到0停止。所以仿真20个顾客。

核心考点：理解TERMINATE参数 + START配合控制仿真时长

场景

原理

用一个独立的GENERATE-TERMINATE段做"计时器"。服务流程的TERMINATE不带参数（减0），只有计时器的TERMINATE带1。START设为1，计时器产生一个实体经过TERMINATE减1，计数器归零，仿真结束。

第一段TERMINATE无参数：顾客离开系统，但不影响终止计数器。系统不会因为服务完顾客而停止。

第二段GENERATE 480：在480时间单位后产生一个"计时"实体，这个实体经过TERMINATE 1让计数器从1变成0。

START 1：和计时器的TERMINATE 1配合，被减一次就归零停止。

思路

完整程序（方法一：嵌套TRANSFER）

注意：三种服务共用同一个SEIZE/RELEASE和QUEUE/DEPART，只有ADVANCE不同。DEPART放在SEIZE后面（三种服务前），RELEASE放在三条路汇合后。

概率计算：第一个TRANSFER分出10%。剩余90%进入第二个TRANSFER，其中.333≈1/3去烫发（90%×33.3%≈30%），其余60%理发。

TRANSFER P,1,0 的含义：取参数1的值，加上0，作为目标模块的行号。如果P1=1就去第1个ADVANCE，P1=2去第2个，P1=3去第3个。要求三段ADVANCE按顺序紧挨排列。

FUNCTION分流更精确：累计概率0.60→1, 0.90→2, 1.0→3，完全对应60%/30%/10%。

第一问：都忙就离开

思路

顾客偏好A>B>C → 先试A，A忙试B，B忙试C，C也忙就走。这正好是TRANSFER BOTH嵌套使用。但BOTH只能试两个，所以需要用GATE NU（设施未使用）来串联判断。

为什么用GATE NU而不用TRANSFER BOTH？因为BOTH模式如果两个都忙会让实体等待，而这道题要求"都忙就离开"。GATE NU可以在不满足时跳到指定标签，实现"不等直接走"。

等等，上面的顺序有问题。应该是工序1完成后先释放减压器再进缓冲区：

; 修正后的工序1→缓冲区1→工序2流程： ENTER PRESS ;占减压器 ADVANCE 38,12 ;加工 LEAVE PRESS ;释放减压器 ENTER BUF1 ;进缓冲区（满则等，但减压器已释放） ENTER SPIN ;占细纱机（满则等，但在缓冲区里等） LEAVE BUF1 ;进了细纱机，离开缓冲区 ADVANCE 320,120 ;细纱加工 LEAVE SPIN ;释放细纱机

这道题的核心就是理清ENTER和LEAVE的顺序：先LEAVE上游设备 → 再ENTER缓冲区 → 再ENTER下游设备 → 再LEAVE缓冲区。
